## 二、根因确认：机制层，不是调参

中文多子句 + 否定宾语位置不定 → "决定内容在哪一段"无确定性答案。
取首句漏标签关键子句、取整段分母拉大包含度归零、取锚点切片切掉宾语——**三口径死在不同地方，
证明是机制问题不是阈值问题**。纸面预期（A+B+C 6/D 3）错得远，因为它假设"每句有属性词+取值段"，
真实文本不这样写。**停，不出 v4，背书。** 再调就是拟合 12 条。

## 三、深层教训：断言层让规则干了理解的活

断言层失败的真正原因：**它要求规则做语言理解**（从中文多子句里定位决定内容），
而这是 LLM 擅长、规则做不到的。尺子"必须确定性"的要求，适用于**判等**，不适用于**抽取**。
我们把抽取（理解）和判等（比较）混在一层，所以失败。

→ **正确的分工：模型做归一（理解，非确定性，钉表头），尺子做判等（确定性，可复算）。**
这不是放弃"尺子是量具"原则，是把它用对地方：量具负责判等，被测对象负责理解。

## 四、三条出路裁决

**第三条（归一交网侧）：批准，方向。** 抽取器直接输出结构化「对象:属性:取值:极性」，
尺子只做确定性元组判等。理由：把"无法确定性抽取"放到不该由规则承担的位置（模型侧），
尺子保持零模型可复算。模型本来就被测、本来就非确定性，归一交给它是用其所长。

**四条条件：**
1. **schema 判据先于代码**：先定输出契约（对象 / 属性[10类] / 取值 / 极性 ¬X），再改 prompt。
2. **网的三元组质量要单独验**：归一成为新瓶颈，必须量网抽出的三元组对不对（对 gold 验），
   不许假设结构化输出=正确三元组。
3. **尺子确定性判等**：元组比对零模型，表头钉 promptVersion/model/seed；非确定性限于网侧。
4. **两段两指标分报**：网抽取质量（模型）+ 尺子判等精度/召回（确定性）分开报，
   才知道哪段限制召回。12 正例 + gold-20 当网结构化输出的验证集。

**第一条（句级对齐）：可作廉价确定性探针/基线。** 分句逐句配对能救 #1，但巧合子句过配风险
要单独量。同范式（规则做理解）的修补，不根治；值得便宜试一次当对照，不重投入。

**第二条（关键名词+极性）：否。** 退回 entity-v2 天花板，补不了什么，已知水平。

## 五、网轨张力的诚实说明

dsh 主动指出这与"网轨收手"有张力。**澄清**：r12 网轨降级是针对"用 prompt 追形状覆盖"
（且基于已纠正的事实摘录器误诊）。第三条是"用 prompt 追结构化输出"，是输出格式/质量轴，
不是形状覆盖轴——不同目标，无实质矛盾。**但确实是转方向再碰网，承认。**
原则没破：尺子仍零模型判等，模型仍是被测对象做理解。

## 八、一句

断言层失败不是坏消息，是量具原则的一次校准：**确定性属于判等，不属于理解。**
让规则去中文多子句里定位决定内容，是让量具干被测对象的活。第三条把活分对——
模型理解、尺子判等——这才是"尺子是量具"的正确实现。停得对，转得对。
