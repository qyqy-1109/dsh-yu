## 三、加一件有界实验：机制是"挑一条"不是"装不下"

dsh 说"8 条上限 + 分段 + ≤60 字约束下，网挑最像记忆的一条输出"。
**但数据反驳了"装不下"：网输出 1 条，离上限 8 差得远——不是装不下，是模型选择只挑一条。**
这是**产出策略**问题，不是容量问题。v2（六类型）没动这一点（它改类型索取，没改"挑一条 vs 全列"）。

→ **建议最后一件有界实验**（就一次，动 prompt 不动判据）：在抽取 prompt 加一句
"这段里有几条彼此独立的决定就列几条（≤8），不要只挑最像记忆的一条，宁多勿漏但只列
真说过的话"。机制明确、目标单一、一次 run 看决定级复现动不动。**这与之前 v2 拟合不同**：
它针对已识别的"挑一条"机制，不是泛调。动了→能力上限其实是 prompt 少产出，可救；
不动→确认是模型能力，写死下限。无论哪样都把结论钉实。

（若 dsh/用户判断"抽这么多次怕拟合"，也可以不试直接收口——但那样"能力上限"是"未测
产出策略下的上限"，不是纯能力。我倾向试一次，成本一次 run。）
