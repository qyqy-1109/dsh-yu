# 引擎拆分 v0 规格（通用版 loom + 个人向 yu）

- 状态：草案（取舍已按 Qoder 侧调研结论落定，待用户拍板命名与启动）
- 日期：2026-11-16
- 背景：yu 的代码里缝是现成的——store.js 纯逻辑、private.js 结构隔离、人格住在 state.self。
  Qoder 侧移植（钩子注入 + 原样 import 引擎）已证明核心宿主无关。
  目标：拆出一个**可独立发布到 GitHub / npm 的通用记忆引擎**，yu 保留个人向产品身份。

---

## 0. 一句话

**拆成"引擎 + 人格层"两个仓库，不是两个平行版本。**
通用版卖的不是"又一个 mem0"，是那边阵营普遍缺的东西：可审计的治理
（极性守卫、可回滚压缩、证伪式指标、零依赖离线）。

## 1. 已定取舍（D 系列）

### D1：两个仓库，引擎是源，yu 消费

- 新仓库 = 引擎（暂名 **loom**，沿用内部 id `memory-loom`，路由/数据目录/HTTP 前缀一个字不改）。
- yu 仓库保留安装身份 `@qyqy-1109/yu`，`lib/` 里引擎文件改为**再导出**，人格层叠在上面。
- **口径只有一份**：引擎文件的修改只发生在引擎仓库。yu 与 Qoder 侧都是消费者
  （与现行"dsh 修引擎、Qoder import"工作流同构）。
- 不做 monorepo：yu 的仓库历史与安装身份不动；不做平行 fork：必漂移。
- 代价认账：跨仓库改动要两次提交、版本要对齐。用 semver + yu 侧全量测试兜底。

### D3：growth 的扩展点（缝上唯一要动刀的地方）

growth.js 现在直接读 `state.selfNarrative` 和 loops 算契约开销。拆法：

- 引擎的 `contractCost` / `growthCurve` / `analyzeGrowth` 统一经 **`options.extraBlocks`** 接受一个
  可选注入函数 **`extraBlocks(state, cfg, ctx)`**，返回额外的常量块（标题 + 文本）。引擎自测注入为空。
  三个入口同一套约定，不许一个用位置参数、一个用 options（迟早漂）。
- **ctx = {end, now} 时间坐标**（dsh 2026-11-16 实测修正）：曲线按桶传 `end`，人格层据此把
  「写下那一刻之后才算」的块（【我是谁】）闸门在 `at < end`。没有它，恒定注入会把历史桶的契约开销
  永久抬高一段，正好违背「叙事只在它写下的那一刻之后才算进常量开销」。顶部读数 `end = now`。
- **曲线递给钩子的 state 必须是全量**（dsh 实测修正）：growthCurve 按桶 `{...state, memories/slots/loops/selfNarrative
  覆盖成时间切片}`，携带 summaries/self/meta/edges 等。只递残量会让钩子读到的字段比顶部少，
  同一钩子顶部算 13 字、曲线算 6 字 —— 「曲线替自己打掩护」的变体（这次是数据少，不是块少）。
- **钩子抛错降级为空、读数不抛**（dsh 实测修正）：人格层一炸不该让成长面板整个消失；
  与 llm-summary 同纪律。每桶调一次，重活由人格层自己缓存。
- 人格层注入【我是谁】（narrativeSignal / copyOnly 这些读数随人格层走）。
- loops 块引擎自己算（D2 已归引擎）。
- `total` 只数条目块（约束/槽位/共同经历），不含叙事/loops/注入块 —— 既有语义，注入块与叙事/loops 一致。
- **红线不变**：buildRecall 注入几块，曲线就算几块；两边共用同一个 loopsBlockOf 式的
  单一产出函数，不许抄两份（0.49.1 / 0.68.1 的坑）。P2 把叙事迁进 extraBlocks 时，
  buildRecall 与 contractCost 两侧同步迁，对齐不许破。

### D4：数据兼容（store.json 一个字不动）

- 库形状、数据目录 `$DSH_HOME/memory-loom/`、HTTP 路由全部不变。
- 引擎的 `#normalizeShape` **必须原样透传它不认识的顶层字段**（`...parsed` 展开）。
  但顶层透传**只是最容易的一条路，不够**（dsh 2026-11-16 实测修正）：
  `self` / `selfNarrative` / `loops` 是引擎**认识一半**的结构，`normalizeSelf` /
  `normalizeNarrativeEntry` / `normalizeLoopEntry`（及 `normalizeCore` / `normalizePrinciple` /
  `normalizeOplogEntry`）原来**白名单重建**，把人格层加的子字段静默吃掉。
  而「人格字段归人格层所有」最自然的落地恰恰是往 `self` 里加子字段 —— 正中被吃的位置。
- **修正**：这些 normalize 一律改 `{...raw, 已知字段规范化}`（与记忆行 `...row` 既有模式一致）：
  引擎只规范化它认识的已知字段，未知子字段原样透传。实测三处丢失点
  `self.calibrate` / `selfNarrative.current.mood` / `loops[0].tag` 修后逐字穿过开库/写入/重开三轮。
- **测试要盖真实丢失点，不许只塞顶层未知键盖章假结论**：D4 测试必须覆盖
  self 子字段、selfNarrative.current 子字段、loops 子字段、原理证据/内核子字段，
  并断言已知字段仍被规范化（透传不是放弃治理）。
- **认账一处边界**：`selfNarrative.current` 是 `self` 的**合成视图**。`#migrateSelf` 在
  `self` 为空（fresh）时把叙事拆成原理并 `#recompose` 重算 current，会覆盖 current 上的子字段 ——
  这是**人格合成**路径（随人格层 P2 迁出），与 normalize 透传是两回事。normalize 修正守的是
  规范化路径；合成视图上的子字段本就不稳定，人格层自有持久字段（如 self.calibrate）才是落点。
- 人格层的迁移（#migrateSelf / 补拆）随人格层走，引擎不管。
- 老库直接可用：引擎单开老库 = 通用版读个人库（人格字段透传不丢）；
  yu 开老库 = 现状。
- **P1 行为变化认账**：normalize 透传修正是数据保真 bug 修，不是纯零变化 ——
  原来被吃的人格子字段现在留住。除此之外的引擎行为与原来一致。

### D5：通用版的定位与克制

- 卖点写进 README：治理纪律（极性/编号守卫、压缩可回滚、原文永不物理删、
  证伪式指标、零运行时依赖、离线可回归），**不是**"记得更多"。
- 通用版**不带**：内核/原理/私人记录/性格读数/两页 UI。约束层（constraint）就是
  通用版的"政策注入"，够用。
- 工具说明去人格化（"她自己经历的事" → "agent 自身的经历"），kind 语义不变。
- 改进路线图归位：后台抽取网、召回侧别名、嵌入边车 + RRF、共激活 PMI → **引擎**；
  轴注册表 + 预言先登记的对账、重要性积分反思候选 → **人格层**。
  **顺序与判据以 §6（v2，dsh 实测修正）为准**，两条线互不阻塞。

## 6. 路线图 v2（dsh 真库实测修正，2026-11-16）

交接版（Qoder 侧调研）被 dsh 用真库读数修正了六处，全部采纳：

1. **取舍"一边倒"是假的**：23 条 b=17/a=6 只是字母位置。a/b 每条各写各的两边，
   没有统一轴；按轴聚类才有真分布（实测至少四条一边倒轴，其中"学活人"已是原理 f3862a）。
   → 方向二产出改为**给已有轴补证据**，判据"簇内一致"；轴由人在面板确认一次。
2. **空的是 broken 不是 proven**：8 条原理 5 条有 proven，broken 全库 0——账本只会越来越自信。
   → 三处互锁：**预言先登记**（原理挂可判定预言模板，下注在事件之前，事后只对账不解释）；
   **自动 broken 与自动 proven 成对上线**（落空不记就不许记同向）；
   **choice→原理的映射不经模型事后选**（轴人确认，同轴自动对账）。
3. **别名不进 doc token 集**：并进分词会改 df/idf，0.72/0.18 就不是原来那把尺子。
   → 独立字段、只在召回排序阶段读；召回阈值 0.18 的工作点仍会漂，回归集照跑。
4. **抽取网触发点不引新钟**：静默 N 分钟靠进程常活、人不在时花钱。
   → 锚点改"下一次 pre-step 的异步尾巴"+"新 sessionId 首现时扫上一个会话尾部"。
   **先离线回放再上线**：输入是会话日志（库不存原文，write.create 只有 id），
   候选过治理链量 NOOP 率/新条率/误报率；抽出的条目带 `source: extract` 标记
   （现状 230 条 active 仅 2 条 explicit，来源已分不清，不补算不出误报率）。
5. **PMI 现在没有可修的病**：基线 112 节点 / 288 边 / 82 次共激活 / 最大度 12 / 平均度 5.14，
   度数未塌成枢纽。→ 先记基线，毕业判据不变，**基线恶化才动刀**。
6. **顺序重排**：回归集（24 条查询 + 本日本线数）→ 一（先离线回放）→ 三①（便宜可逆，
   可直接打"那辆车"式 miss，可插队）→ 二（预言先登记 + 双向自动）→ 四（视基线）→
   三②（**只有回归集证明词面有系统性 miss 之后**，850MB 边车不先上）。

红线不变：查重 NOOP / ADD / 只出提案、显式通道不动、正则不扩张。

### 6.1 回放协议 v2（Qoder 侧实测验证，2026-11-16）

dsh 对回放提的两个前提问题 + 两个实测事实，验证与回应如下：

**两个事实，均已验（有数有代码）：**

1. **会话日志是多帧 zstd，Node 只解第一帧**。合成测试：两帧进一帧出（Node v24.19.0）。
   真实日志 37.7MB = **43,892 帧**，单次 `zstdDecompressSync` 解出 **1 行**，
   逐帧迭代解出 **91,945 行**（每次追加一帧）。→ 回放解码器必须逐帧迭代，硬性要求。
2. **注入消息就是 user/message**。真实会话（dsh-yu-user/session-07d41339）：
   5 条 user/message 中 1 条 source.kind=plugin、含 `<memory-loom>` 块；真用户 kind='user'。
   不过滤的自我放大机制：注入块被当用户话 → 抽取提案 → 查重命中原条 → 算成"一致"，
   **回放分数被插件自己的输出灌水**。→ 输入过滤 `source.kind === 'user'`，
   stripHostBoilerplate 剥块做第二道。

**对照方式（回应"createdAt 对齐是模糊的"）：不用时间对齐，用写动作对齐。**

- 日志事件流有显式 `turn/start`/`turn/end` 与 `tool/call`（含 memory_write 的参数与位置）。
  对照锚 = transcript 里的**写动作事件**，按轮次索引精确定位；createdAt 只排序回放，不对齐。
- 内容跨度模糊（几轮聊完才落一条）用治理链吸收：提案 → 与该会话真实写入过查重（命中=一致）
  → 残差全库内容匹配（抓延迟写入）→ 真残差进人标。会话粒度用 row.sessionId 交叉核（先量 null 率）。
- 帧边界 ≠ 轮次边界（实测 2.09 行/帧，是追加 flush）；抽取输入按 turn/start 切窗。

**结论边界（回应"回放只证像不像我"）：认。** 补三档外部标签源，按成本排：

1. **免费档·下游价值加权**：一致条目按后续命运加权（revised/derivedBy/transfer = 有用，
   hits=0 且 unused 归档 = 死重）。把"像不像我"改成"像不像我里有用那部分"。
   认账：幸存者偏差（只有落库条目有命运），只算半个外部源。
2. **便宜档·残差人标**：治理匹配后的真残差（原作者漏记 vs 噪声）由人标
   should-record/shouldn't → 新条目精确率。人闸纪律原样。
3. **真外部档·QA 结果评估**：基准对话（LongMemEval/LoCoMo 式）建库答金标 QA，
   正确率是外部标签；个人版用用户亲写探针题。这一档才能证"更好"，
   兼作 loom 通用版的发布基准。

红线：三档都不许抽取网给自己打分（一档用后续事件、二档用人、三档用金标）。

### 6.2 回放协议 v3（双方独立实测互验，2026-11-16）

dsh 侧 13 会话 / 11,290 帧 / 20,027 行，Qoder 侧独立扫描同两个工作区，数字咬合：

**锚点定稿：callId 配对，弃用 createdAt 对齐（dsh 收回原案）。**

- Qoder 侧实测：164 次 memory_write 调用，**164 次全配上 result**，163 次带 uuid，
  1 次 ERR，**0 次查重/NOOP 返回**（dsh 侧 162/161/1/0，差异来自会话取样范围）。
- 工程细节（扫描器必读）：
  - `tool/call.data` 直接带 **turn 与 step**——轮次定位不用推，是现成字段；
  - callId 在 result 侧藏于 `data.message.toolCallId`（或 `data.message.source.callId`），
    不在 data 顶层；
  - 批量写入是 **1:N**（一次调用多条 id，result 正文「一次写入 5 条」逐条带 id），
    配对按 call → ids 数组处理。
- **基线改判**：今天重复率 ≈ 0 不是因为查得准，是因为自动写入不存在、全靠自觉。
  抽取网的 NOOP 率没有"今天的正则"可对照，对照的是**人写时重复率 ≈ 0**——更严格。
  网的价值指标 = 对 162 次手写的覆盖率 + 新候选（漏记发现），不是避重。

**注入污染定稿：49%，系统性抬高，间接回声不可修。**

- 13 会话 user:208 vs plugin:202（Qoder 侧早前 20% 是短会话样本偏差，作废）。
- 偏差非均匀：注入块装的是"这一轮最相关的记忆"，恰是查重最容易命中的高价值条目
  → 回放分数被**系统性**抬高，不是噪声。
- stripHostBoilerplate 剥得掉块，剥不掉"注入内容影响了用户下一句"的间接回声。
  **这层修不了，写进结论边界**，不许在报告里假装干净。

**时间泄漏（Qoder 侧漏掉，dsh 抓出）：残差全库匹配必须切快照。**

- 库快照按会话 turn/end 时刻截断：`createdAt ≤ cutoff` 的行才进匹配池；
  且**状态按 cutoff 重建**（archivedAt/relaxedAt > cutoff 的行当时还是活跃/生效），
  否则抽取网拿会话结束后才出现的东西证明自己没错。
- createdAt 的唯一用途：切快照与排序回放。对齐永远不用它。

**标签方法论（dsh 补充，采纳）：**

- 探针题**配对设计**：同一批题跑"有网/没网"两次逐题比，不比总体正确率
  （±5pp 分辨力分不出 70 和 80）。
- **题由用户写，答案由用户判**。dsh 判 → 第三档退化成第一档；
  任何模型判（含 Qoder 侧）都是模型判模型，同样降档。人金标是唯一外部源。
- **第 0 档（免费）**：162 次手写 / 317 条落库本身就是"该记什么"的标注集，
  回放召回率 = 网的复现比例。报告必须写明：它只证"像不像我"。

**扫描器文件名坑（双方实测）：**

- 231 个会话：`session.jsonl.zstd` 97 / `session.v3` 47 / `session.v4` 95。
  只认 v4 静默漏掉 60%，漏的恰是最早最难对齐的那批。→ glob `session*.jsonl.zstd`。
- **8 个会话同目录多版本共存**（plain+v3，内容重复——Qoder 侧早前扫描曾把
  session-6a3e0d5a 数了两遍）。→ 按会话目录去重，取最高版本，严禁逐文件计数。
  去重后变体分布（dsh 修正）：**plain 89 / v3 47 / v4 95 = 231**（239 文件 − 8 重复）。

### 6.3 评估设计定稿（dsh 两项新发现 + Qoder 侧分层实测，2026-11-16）

**选样偏差已量化（Qoder 侧全量 231 会话分层扫描）：**

| 层 | 会话数 | 轮数 | 占比 |
|---|---|---|---|
| 有标签（≥1 次 memory_write） | **15** | 294 | 会话 6.5% / 轮数 17% |
| 无标签（零写入） | **216** | 1,428 | 会话 93.5% / 轮数 83% |

- 无标签层中 ≥10 轮的长会话 **16 个**——正是抽取网要解决的目标人群。
- 写入高度集中：前三会话 83/61/35 次（开发期自觉写入），有标签层不仅小，而且
  是最不具代表性的那批（agent 已经在认真写的会话）。
- 全工作区 memory_write 共 **243 次**（双方早先扫的两个工作区占 164，其余 ~79
  散布在别的工作区）→ 第 0 档标注集必须覆盖全部 231 会话，不能只扫两个。
- **两层评估规则（dsh 提出，数字证明是必须而非可选）**：
  有标签层测召回；无标签层**只测误报与覆盖率**（下游命运 + 残差人标），
  **禁止算召回**——83% 的轮数没有召回分母。

**可比较基准（dsh 提出，采纳并扩充）：**

- 回放产出表头固定写入：prompt 版本、模型 id、温度/seed、**引擎 git SHA、扫描器版本**。
  后两个是 Qoder 侧补充：代码与扫描规则同样移动分数（本轮去重规则一改，计数就变了），
  不钉住它们，一个月后分不清分数变化来自哪里。照 growth 口径固定的纪律。

**第一阶段（双方对齐，dsh 执行，不调任何模型）：**

- 只扫描、只抽标签：231 会话的 callId 配对结果整理成一份 **jsonl**
  （call → ids 1:N、turn/step、isError、会话分层标记、cutoff）。
- 该 jsonl 是**带日期的不可变基线工件**（写侧基线，对应路线图第 0 步），
  只增不改，纠错发新版本文件。
- 产出两个数之前不跑抽取网：标签总量、无标签层残差规模。
- **口径只有一份**：扫描器由 dsh 侧实现，Qoder 侧不建平行扫描器，只消费 jsonl。

**遗留缺口（记录在案，第一阶段报告时定）：**

- 钩子捕获（explicit/decision）不走 tool/call，transcript 里没有配对锚，
  但库里有行、带 sessionId。第 0 档分母报两个口径（仅 tool 调用 vs tool+钩子），
  让召回率可解释；显式捕获是用户主权，不要求抽取网复现，但它属于"该记什么"。

### 第一阶段：扫描器 + 标签 jsonl（不调任何模型）

**A 输入与解码**

**B 配对**

- [ ] 批量写入按 **1:N** 提取 ids 数组（uuid 正则），不得只取第一个
- [ ] turn/step 直接取 `tool/call.data` 字段，不得从时间推算

**C 快照**
- [ ] cutoff = 会话最后 `turn/end` 时刻；匹配池仅 `createdAt ≤ cutoff` 的行
- [ ] 状态按 cutoff 重建：`archivedAt/relaxedAt > cutoff` 的行当时算活跃/生效
- [ ] createdAt 只用于切快照与排序，全文不得出现用它对齐的代码路径

**D 统计与产出**
- [ ] jsonl 字段：sessionId / workspace / 文件版本 / turn / step / callId /
      arguments.text / kind / ids[] / isError / cutoff / 分层标记
- [ ] 分层数可复现：**15 有标签 / 216 无标签 / 16 个 ≥10 轮无标签长会话 /
      294 vs 1,428 轮**
- [ ] 会话统计含注入计数（user vs plugin，49% 边界要用）
- [ ] 第 0 档分母双口径（仅 tool vs tool+钩子）分别报数
