# 判据 v1.2（2026-11-19 已批）：什么叫"同一命题"

v1.1 解决的是"该不该记"。这一版解决另一个问题：**尺子配的这一对，是不是同一件事**。
它是 entity-v3 的地基——判据先定，代码后写。

## 为什么需要这一条

entity-v2 问的是"共享稀有实体吗"，那是**话题级**相似；金标问的是"同一命题吗"，那是**命题级**同一。
两者在 20 条分层抽样上的差距就是全部误差来源：命中组 10 条里只有 5 条是真同一命题（n=10，CI 宽）。

五条错配的模式高度一致，全是**命题类型或主语错位**：

| 样本 | 候选的命题 | 标签的命题 | 错在哪 |
|---|---|---|---|
| #2 | 用户对流畅度**敏感**（特质） | 面板**必须有帧率保障**（要求） | 类型不同：特质 ≠ 要求 |
| #6 | 只给判断、决定权归人（**交互原则**） | 内核 **vs** costume 的**定义澄清** | 类型不同：原则 ≠ 定义 |
| #8 | 造一个有倾向欲求的人（愿景**侧面 A**） | 有自己的自主生活（愿景**侧面 B**） | 同为愿景，断言对象不同 |
| #9 | **偏好**用官方 API 做归纳 | patch.yml 的**配置事实** | 类型不同：偏好 ≠ 配置 |
| #10 | 全部能力一起推进（**策略**） | 造有倾向有欲求的人（**目标**） | 类型不同：策略 ≠ 目标 |

## 同一命题 = 三层都对上

一条命题 = **主语** + **类型** + **断言**。配对成立要求三层同时对上：

1. **主语同一**：这条讲的是谁/什么东西（用户本人 / agent 自己 / 插件或面板 / 某个流程 / 某份文档）。
   主语不同一律不同命题，**哪怕话题完全一样**（#8 就是两条都在讲"想要什么样的人"，但一条讲自主生活、一条讲内在倾向）。
2. **命题类型同一**：取有限几类，别自造细分：
   - 事实（发生过什么、配置是什么、库里有几条）
   - 偏好 / 特质（用户喜欢什么、对什么敏感）
   - 要求 / 禁令（必须 / 不许 / 别再）
   - 评价（这次好不好、够不够）
   - 目标 / 愿景（要做成什么）
   - 策略 / 方法（怎么做、按什么顺序推进）
3. **断言不矛盾**：同一主语同一类型，但一条说"要"、一条说"不要"，那不是同一命题，是**一对反例**（这种要单独标 `contradicts`，不是 pairCorrect）。

## 两条边界规则（本轮实测出来的）

**① 同一决定的两个侧面 ≠ 同一命题。** 它们都该记，但配对判定是"否"。
判定配对精度和判定"该不该记"是两件事，混在一起会互相掩盖——5 条配对错里候选大多该记（错在尺子，不在网）。

**② "已写在 README" 不影响配对判定。** 那是"该不该记"的问题（v1.1 已裁：实现细节才排除），
不能拿来当"配不配得上"的理由。

## 输出格式（人标）

```json
{"n":1,"verdict":"该记|不该记","kindFix":"world","pairSame":true,"contradicts":false,"subject":"用户","type":"目标","reason":"…"}
```

`pairSame` 只对命中组有意义；未命中组留 `null`。

## entity-v3 的候选机制（等本判据定稿后再选，现在不写代码）

1. **类型兼容门**：候选与标签的命题类型不同 → 直接判非同一命题（这一步能砍掉 #2/#6/#9/#10 四条）；
   类型从 kind + 文本特征判定（要求类看"必须/不许"，偏好类看"喜欢/敏感"，事实类看数字与配置标识）。
2. **主语匹配**：主语不同 → 非同一命题（能砍掉 #8）。
3. **词面只做候选召回**，不做最终判定：v2 的实体重合降级为"候选生成器"，配对由 1+2 定。
