# 候选标注判据 v0（草案，待用户确认；两个标注者共用，分歧交用户裁）

## 该不该记（三天测试 + 行为影响）

一条候选**该记**，当且仅当：
1. **三天后仍成立**（不是当下 staffing、不是"正在做"、不是时点评价）；
2. **会影响未来行为或判断**（不是代码/README 已体现的实现细节）；
3. 不是过程记录、一次性指令、代码或文件内容。

**被后续讨论推翻/修改的要求 → 不该记**（抽取窗看不到结局时，标"疑似过期"交人核）。

## kind 判据（收窄版）

| kind | 门槛 | 反例 |
|---|---|---|
| constraint | **硬性、长期、不允许违反的行为禁令**（"不许/必须/别再"） | 设计要求、质量期望、UI 摆放 → 不是 constraint |
| world | 长期设定、结构、**已定稿的设计结论与否决** | 当下状态、过程描述 |
| fact | 关于用户的稳定事实/偏好/特质 | 时点评价、一次性指令 |
| episode | 具体共同经历事件（带场景/重要度） | 评价快照、迭代流水 |
| self | agent 自身的判断/失误/工作方式（第一人称） | 用户的经历 |

设计否决（"不要半透明"）归 world 还是 constraint：**争议项，交用户裁**（v0 倾向 world）。

## 标注输出

每条：`{n, verdict: 该记|不该记|争议, kindFix, reason}`。
两个标注者**各自独立标全部 16 条**（不是各标一半——没有重叠就没有分歧率），
分歧项 + 争议项交用户裁决，裁决结果才是"该记什么"的尺子。
模型互相同意不算金标（shuttle D2）。
