# attr 定义 v1：12 类的正例与反例（判据先于标注，网与人标同源）

v1.4 只给了 12 个类名，没给边界。结果是网把「归属」当成"属于哪家公司"用
（#14「面试公司为温州方舟永道科技有限公司」→ `归属`），而判据里它指的是**层级/责任分配**。
类定义模糊会让 attr 一致率混进"定义误差"，不能全算网的错 —— 与 subject 那次同款教训，
所以这一版把每类的正例/反例钉死，**嵌进抽取提示词与标注指南，两边同一份**。

## 判类顺序（先看这条决定"改的是什么"）

1. 改**归属/责任**（谁负责、归哪层）→ `归属`
2. 改**两个东西之间的关系**（配不配、联动、缺一不可）→ `关系`
3. 改**底线/红线**（不许做、必须守）→ `底线`
4. 改**判断或汇报的口径**（怎么算、怎么说、先量还是先猜）→ `口径`
5. 改**推进顺序**（先做哪个、再接什么）→ `顺序`
6. 改**出了问题怎么办**（怎么排查、别绕圈）→ `排障`
7. 改**外观/动效/质感** → `风格`
8. 改**东西摆在哪** → `位置`
9. 改**留不留、留多久、留哪个** → `存留`
10. 改**叫法**（名字、称呼、自称）→ `命名`
11. 改**选哪个方案/哪种技术** → `选型`
12. 改**结论本身**（实验结论、判断结果）→ `结论`

## 12 类正例 / 反例

| attr | 正例 | 反例（应归到哪类） |
|---|---|---|
| 归属 | 轴注册表归人格层；引擎只带 choice；审查归 qwen | 「面试公司是温州方舟永道」→ `结论`（是事实不是分工）；「插件名叫记忆海」→ `命名` |
| 关系 | 记忆与人格缺一不可；光效与呼吸灯联动；太极两半 | 「先做成长再接手脚」→ `顺序` |
| 底线 | 不许编造；不许抽取网自评；不再管方舟永道 | 「帧率要有保证」→ `风格`（产物质量不是行为红线） |
| 口径 | 先量再下结论；used 口径废弃；对照按轮次锚对齐 | 「直说但先给理由」→ 也是口径，可接受；「帧率保证」→ `风格` |
| 顺序 | 先做会成长的自我再接其他能力；先方案 2 验证再上 3 | 「全部能力一起推进」→ `选型` 或 `顺序`，看句子重心在"哪个方案"还是"哪个先" |
| 排障 | 出问题先换方案别绕圈；debug 靠日志不靠猜 | 「不喜欢反复绕圈」→ `口径`（偏好）还是 `排障`（做法），看主语是偏好还是做法 |
| 风格 | 面板不要半透明；纯星图派；帧率要有保证；星云底+丝带线 | 「按钮放编辑按钮旁」→ `位置` |
| 位置 | 详情就地展开；入口放左侧导航；右上角下方 | 「详情窗口盖在所有图层之上」→ 已推翻；若成立属 `位置`+`风格` 交界，按"摆在哪"取 `位置` |
| 存留 | 历史回顾只留历史部分；私人记录保留、位置自定 | 「只在求职工作区谈找工作」→ `归属`/`口径`（场合限制），不是存留 |
| 命名 | 助手定名小鱼；插件名记忆海；项目名旧识 | 「用户称呼我为小鱼」→ 同一件事，`命名`；「公司名」→ `结论`（事实） |
| 选型 | 用官方 DeepSeek API 做归纳；采用方案三；TDD | 「底座不能做成插件」→ `底线` 或 `归属`，不是选型 |
| 结论 | 时间刻实验效果生硬、现在做不到；可追溯链路未接通；写入提醒会抛 TypeError | 「不做浮层」→ `风格`（设计否决）；「不再管方舟永道」→ `底线` |

## 两条硬边界规则

1. **"属于哪家公司/叫什么名字/是什么事实"不是 `归属`**。`归属` 只用于**层级与责任分配**（谁负责、归哪一层）。
   公司归属、身份事实 → `结论`（事实型判断）。
2. **产物质量要求（帧率、质感、流畅）归 `风格`，不归 `底线`**。`底线` 只给"不许我做某事"。

## 已知局限

12 类是**粗分类**，交界必有争议（如 `口径` 与 `排障`、`选型` 与 `顺序`）。
交界样本在标注时标 `attrAmbiguous: true` 并写明另一候选类，**不硬凑**——
attr 一致率报两个数：全体一致率，和剔除 `attrAmbiguous` 之后的干净一致率。
