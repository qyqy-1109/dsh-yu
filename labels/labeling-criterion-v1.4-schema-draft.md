# 判据 v1.4（草案）：结构化决定 schema —— 模型理解，尺子判等

v1.3 的断言层在 12 条双标集上失败（三种取值口径覆盖 0.333 / 0.25 / 0.000，gold-20 捞回 0）。
根因不是词表，是**让规则去干理解的活**：从中文多子句里定位"决定内容在哪一段"，规则做不到。

所以分工改一处，原则不变：

- **抽取（理解）= 模型**，非确定性，钉表头（`schemaVersion` + model + temperature）；
- **判等（比较）= 尺子**，确定性，零模型，可复算。

量具原则没破：确定性属于判等，不属于理解。

## 一、schema（抽取器必须输出的四元组 + 两附注）

```json
{
  "kind": "fact|world|constraint|episode|self",
  "subject": "决定的承载对象",
  "attr": "归属|关系|底线|口径|顺序|排障|风格|位置|存留|选型|结论",
  "value": "定下来的那个值（不带情态词）",
  "negative": false,
  "text": "一句话中文（≤60 字）",
  "candidateOf": "窗口标识（sessionId#fromTurn-toTurn）"
}
```

- `subject` **必须是粗粒度闭集之一**：`user | agent | product | project | other`。
  自由文本不可比（"面板"与"记忆面板"是否同主语说不清）；闭集才让判等确定性。
  网侧要把它映射到这 5 类，映射不了的落 `other`。
- `attr` **只能取 12 个维度之一**（闭集，与 `lib/replay-assertion.js` 的 `ATTR_CLASSES` 同源）：
  归属 / 关系 / 底线 / 口径 / 顺序 / 排障 / 风格 / 位置 / 存留 / 命名 / 选型 / 结论。
  取不到就输出 `unknown`（不许自造，不许空）。**判据、代码、网输出三方必须引用同一份枚举** ——
  v1.4 初稿里"命名"漏过一次（口头 10 类、示例 11 个），闭集不一致会让"attr 相等"这条判据失去可比性。
- `value` 必须把情态词剥掉（"必须/要与/要有/应当"不属于取值）。
- `negative` 表示"这条是 ¬X"（否决/不再/禁止/不要）。`不要半透明` → `value:"半透明", negative:true`。

## 二、判等规则（尺子，确定性）

两条决定同一 ⟺ 四条同时成立：

1. **`negative` 相等** —— ¬X 与 X 不是同一个决定。**这一条永不降级**（与引擎 `isSameClaim` 同纪律；
   降级丢极性会让"不要半透明"配上"采用半透明"，那是判等最不该犯的错）。
2. `subject` 同类 —— 粗粒度闭集相等。任一方为 `other` 时不参与本条件（并计入"subject 未定"单报）。
3. `attr` 相等 —— 同为 `unknown` 时不参与本条件（计入降级）。
4. **取值实体包含**：`|E(valueA) ∩ E(valueB)| / min(|E(A)|,|E(B)|) ≥ τ`
   （实体 = 引擎分词去单字/停用词/虚词碎片；**不是裸串包含**）。

**τ 是暂定起点 0.5，不是定值**。它必须在 12 条双标集 + gold-20 上做敏感性扫描（0.3/0.4/0.5/0.6/0.7），
报出每个 τ 上的 pair/reject precision，**校准后才许钉**。

降级规则（只降条件 2、3，永不降条件 1）：
- 任一方 `attr = unknown` → `degraded.attr = true`；
- 任一方 `subject = other` → `degraded.subject = true`；
- 两者都降级时仍守极性 + 取值包含，并标 `degraded: true` 单独统计（降级占比是读数）。

## 三、网侧三元组质量单独验（条件②）

结构化 ≠ 正确。必须单独量网抽得对不对，指标分开：

- **属性一致率**：候选与标签的 `attr` 相同占比；
- **取值一致率**：`value` 实体包含度 ≥ 0.5 的占比；
- **极性正确率**：`negative` 与人工判断一致的占比；
- **`subject` 映射正确率 + `other` 率**：粗粒度归类对不对，映射不了的有多少；
- **`unknown` 率**：抽不出属性的比例（这是网的读数，不是尺子的）。

样本：12 条双标正例 + 人审池 32 条 useful + gold-20 的 10 对，逐条标"网的输出对不对"。

## 四、两段两指标分报（条件④）

| 段 | 指标 | 谁的问题 |
|---|---|---|
| 网抽取质量 | 属性一致率 / 取值一致率 / 极性正确率 / unknown 率 | 网的（被测对象） |
| 尺子判等 | pairPrecision / rejectPrecision / 覆盖率 / 降级占比 | 尺子的（量具） |

**不合并成一个数。** 只有分开，才知道限制召回的是"网抽错"还是"尺子判错"。

## 五、廉价确定性探针（一次，作对照）

**句级对齐**：分句后逐句比（attr 同 + 取值实体包含 ≥0.5 + 极性同），任一对成立即命中。
确定性、零模型、能救 #1 那类"关键内容在另一子句"的案例。
但它会引入"巧合子句"过配 —— 必须单独量误配率，**只作对照基线，不投入建设**。

## 六、代码处置

- **保留**：极性原语（`polarityOf`，¬X 判定）、属性维度表（10 类，供 schema 与探针复用）、取值实体化。
- **弃用**：`extractDecision` 的取值抽取 + `sameDecision` 的规则归一（v1.3 那条路，标停）。
- **不写**：任何"让规则从多子句里定位决定内容"的新代码。
- 判等层实现待 schema 与网侧质量都验过之后。

## 校准纪律（沿用）

判据先于代码；词条不许从校准集里抄；纸面预期必须写明"是预期不是结论"；
失败的口径要原样报，不许只报有利的那个。
